# 青养 · 食疗健康生活（课程作品「食疗增益——青养」）

> 《人工智能基础与应用》课程大作业作品（AI 辅助开发的药食同源 Web 应用）。

一个**只在本机浏览器里运行**的药食同源 / 药膳 APP。无登录、不联网、无云端，所有数据保存在本机浏览器里，刷新、关闭、重启电脑都不会丢；支持安装到桌面（PWA）并**离线运行**。

- 在线演示（GitHub Pages）：<https://zhaoqingyun122.github.io/qingyang/>
- 代码仓库：<https://github.com/zhaoqingyun122/qingyang>

## 作品简介

「青养」把 **鉴别 — 剂量 — 药膳 — 记录** 串成一个完整的家庭食疗闭环：

- 药食同源物质（如怀山药与菜山药、杭白菊与野菊花）**外观容易混淆，认错品种则性味和用量都会偏**；
- 网络食疗信息零散、剂量口径不一，家庭烹调时常拿不准**成人、青少年分别该吃多少**；
- 本作品由 AI 辅助完成需求分析、代码生成、测试体系搭建与发布部署，最终形成可直接运行的食疗健康工具，是本课程「AI+食品」方向的实践作品。

## 功能一览

### 四大核心模块

| 模块 | 能做什么 |
| --- | --- |
| ① 首页 · 物质鉴别 | 40 种药食同源物质；关键词搜索（名称/别名/功效）、按类别筛选、卡片/列表切换；**拍照辅助鉴别**（取照片主色给出候选）、**外形特征逐项选择**（形状/颜色/质地/气味/断面）；物质详情含药典条目、外形特征、成人/青少年分龄参考量、适用状况与相关药膳 |
| ② 身体状况 · 药膳 | 12 种常见身体状况；可用自己的话描述症状来匹配；进入后按**物质**列出适用条目，成人/青少年剂量左右分列对照；对应药膳列出用料、做法、适用人群与注意事项 |

| ④ 数据与设置 | 使用统计与 14 天发帖图；内容管理（帖子、鉴别记录、访客）；**导出/恢复本地备份**（.json）；导出帖子为 Markdown；偏好设置；清空与重置 |

## 技术栈

- **零第三方依赖**的纯前端：原生 HTML + CSS + ES Modules（无框架、无构建工具、无 npm 包）
- **IndexedDB** 本地持久化（不支持时降级 localStorage），数据不出本机
- **Service Worker** 离线缓存（network-first：在线取新、断网回退缓存）
- hash 路由单页导航，纯客户端运行，天然适合 GitHub Pages 静态托管
- 开发与测试：Node.js（本地静态服务器 + 测试脚本）、Edge 无头浏览器（端到端）、Python + Pillow（生成 PWA 图标）

## 运行说明（本地）

**方式一：双击 `启动青养.cmd`（推荐）**
- 自动启动本地服务并打开浏览器，地址 `http://127.0.0.1:5173/`。
- 自动选用仓库内 `runtime\node.exe`；没有时也可用系统 Node.js（[nodejs.org](https://nodejs.org/) 下载 LTS）。
- 关闭黑色命令行窗口即停止服务；端口被占用可执行 `node scripts/server.mjs --port 5174`。

**方式二：双击 `启动青养.vbs`（无黑窗口）**
- 后台静默运行本地服务，自动打开浏览器，启动过程不闪黑窗口。

**方式三：直接双击 `index.html`**
- 不需要任何环境即可使用；浏览器文件协议下摄像头等少数能力可能受限，功能一致。

> 数据存放于浏览器 IndexedDB；**换电脑 / 清理缓存 / 重装浏览器之前，请先在「数据与设置 → 本地备份」导出 .json 备份**。不同浏览器数据互不相通，建议固定用一个浏览器。

## 测试与质量

- **静态自测** `node scripts/selftest.mjs`：**661 项断言**全部通过（数据完整性、持久化语义、分龄剂量口径、模板转义、PWA、深色模式、收藏、打卡、购物清单、引导等）。
- **端到端测试** `node scripts/e2e.mjs`：**103 项断言**全部通过（基于 Edge 无头浏览器 + CDP，覆盖全部页面与核心操作流，含刷新持久化验证与完整验收截图在 `scripts/e2e/*.png`）。
- 开发纪律：**完成一项功能 → 先写测试 → 测试通过 → 再提交**；验收前做全量回归。

## 构建与 GitHub Pages 部署说明

- **本项目无需构建**：源码即最终产物（无框架、无编译步骤），本地服务与静态托管用的是同一份文件。
- 发布与调试的运行环境：`node scripts/server.mjs`（默认 127.0.0.1:5173，仅本机访问）。
- **发布副本**位于 `web/` 目录（纯静态站点文件，与根目录源码手动同步，提交前确保一致）。
- **部署方式**：将 `web/` 内容推送到 `gh-pages` 分支 → 在仓库 Settings → Pages 选择 "Deploy from a branch" / `gh-pages` / `/(root)` → 保存后即发布到 `https://<用户名>.github.io/qingyang/`。
- 主分支 `main` 保存全部源码、测试脚本与本文档；发布分支 `gh-pages` 只含站点文件。

## 制作说明（课程要求）

- **AI 工具**：DeepSeek（对话式大模型）——需求梳理、架构设计、代码生成与重构、测试用例设计、食疗资料结构化、报错排查、文档辅助。
- **其他工具**：Windows + Edge（开发与自动化测试）、Node.js（本地服务与测试）、Python + Pillow（PWA 图标）、Git + GitHub（版本管理与发布）。
- **本人工作**：产品定位与需求取舍、界面交互把关、内容准确性审查（剂量/禁忌人工核对）、测试验收、GitHub 发布管理、报告撰写。
- **AI 协作亮点**：AI 生成的代码并非总是正确——「收藏」功能曾因方法同名被类内覆盖而静默失效，由端到端测试抓出并修复；这验证了"用自动化测试给 AI 生成代码兜底"的必要性。多轮迭代细节见课程报告《补充材料：AI 协作与迭代改进》与所附 AI 交互记录。

## 安全口径

- 所有剂量都是**家庭日常参考量**，不是处方，不替代医生诊断与药物治疗。
- 慢性病服药期、孕产妇、婴幼儿、过敏体质请先咨询医师或药师。
- 拍照鉴别只根据照片整体颜色缩小范围，最终请对照外形特征与实物确认，拿不准就不要吃。
